## 一、软件是什么

**一句话**：摄像头/视频拍到学习过程，系统自动识别「事件」（玩手机、看书、写字等），用 AI 理解后存成「记忆」，之后能用自然语言搜索并回放那段视频。全程跑在 Intel AI PC 本地。

**核心价值**：把「海量学习录像」变成「可检索、可回放的记忆」——不用从头翻视频，直接问一句，就能定位到某个时刻、那段画面。

**5 种事件类型**：

| 英文 key | 中文 | 含义 |
|---------|------|------|
| `phone_usage` | 玩手机 | 低头看手机 |
| `start_study` | 开始学习 | 坐到书桌前开始 |
| `open_book` | 打开书 | 翻开书本 |
| `writing` | 写字 | 动笔书写 |
| `leave_study` | 离开学习 | 起身离开 |

## 二、完整处理链路

```
视频输入 → YOLO 检测 → 目标追踪 → 事件引擎 → Qwen-VL 理解 → 视频记忆 → 搜索/回放
   ↑            └── 逐帧持续运行 ──┘        │            │           │
 摄像头/文件     （实时，轻量）          （时间轴推进）  （事件触发）   （检索）
```

关键运行语义（决定了界面上每块内容的「节奏」）：

1. **两种视频源本质相同**：实时摄像头和本地视频文件，进到链路后都被当成一条**连续的「帧流」**处理。本地视频 = 边播放边逐帧喂给模型。
2. **两条不同的更新节奏**：
   - **YOLO 检测** —— **逐帧实时变**（轻量模型持续跑，每一帧都在更新目标）。
   - **Qwen-VL 语义理解** —— **事件触发才变**（只有命中一个事件，才调用 VLM 生成 caption，两次事件之间保持不变）。这是省算力的关键策略。
3. **「采集」与「分析」分离**：打开摄像头/导入文件只是**采集画面**，点「开始分析」才真正启动 AI 链路。

## 四、各区域功能与运行机制

### 4.1 顶部标题
- **显示**：蓝色渐变 logo 方块 + 「AI 学习记忆」主标题 + 「AI Learning Memory · 实时视频智能分析」副标题。
- **运行**：纯静态展示，标识系统身份。

### 4.2 LIVE VIDEO（视频输入）
- **显示**：一个 Tab 切换面板，两个标签：
  - **实时摄像头**：调用本机摄像头，实时显示画面。
  - **本地视频文件**：上传 `.mp4` 等本地视频文件。
- **运行机制**：
  - 这里只负责**采集画面**，此时画面是「裸画面」，尚未叠加检测框、尚未分析。
  - 点下方「开始分析」后，后端 C（检测追踪）才开始逐帧推理，并把检测框叠加到画面上（Day 2 接入）。
  - 「开始分析」/「停止分析」是分析链路的开关，状态圆点从灰「待机」→ 绿「运行中」→ 灰「已停止」。
- **两个源的区别**：摄像头的时间轴是真实时间，文件的时间轴是视频内部时间。除此之外行为一致。

### 4.3 AI Analysis（分析）
- **显示**：一张卡片，分上下两段，各自带一个徽章：
  - **实时检测 `LIVE`**：当前帧检测到的目标（如 `person ×1 · phone ×1 · book ×1`）。
  - **语义理解 `事件触发`**：一段文字描述（如「画面中一名学生正低头看手机…」）。
- **运行机制**（两条节奏）：
  - 上段「实时检测」由 **YOLO 逐帧**更新，跳动很快。
  - 下段「语义理解」由 **Qwen-VL 事件触发**更新，只有命中事件才刷新。
  - 徽章就是为了让用户一眼区分「哪段在实时跳、哪段是 VLM 结果」。

### 4.4 当前事件 Current Event
- **显示**：当前正在发生（或刚识别出）的事件卡片，含中文事件名、英文 key、track 编号、置信度、起止时间。
- **运行机制**：由事件引擎 A 输出，随播放/时间推进**实时切换**。例如视频播到「有人玩手机」这一刻，卡片就变成「玩手机」；行为结束切到下一个事件或回到无事件。**摄像头和文件都有效**。

### 4.5 近期事件时间线
- **显示**：本次分析会话中**已发生事件**的累积列表，每条 = 时间 + 事件名；当前项用蓝点高亮并标「当前」。
- **运行机制**：
  - **实时摄像头**：随真实时间流逝**持续追加**新事件，会话不结束就一直增长。
  - **本地视频文件**：**边播放边逐步生成**——视频播到哪个时间点，才识别并追加哪个事件（不是导入即全部生成）。
  - ⚠️ 待定产品决策：是否提供「全量预分析」（导入后先快进扫一遍、一次性生成完整时间线）。当前默认「边播边生成」。

### 4.6 搜索区「问问你的学习记忆」
- **显示**：一个自然语言搜索框 + 「搜索」按钮。
- **运行机制**：用户输入自然语言（如「什么时候有人玩手机？」），回车或点「搜索」。后端 D 用 Embedding / 向量检索 + Qwen 做语义理解，返回相关结果（Day 5 接入）。

### 4.7 搜索结果 + 回放
- **显示**：一张整块表格（时间戳 / 事件 / 描述 / 视频片段），下方一个「回放选中片段」按钮，表格上方有交互提示。
- **运行机制**：
  - **选中整行**：点击表格任意单元格 = 选中该整条结果（点描述、点时间戳都一样），回放始终取该行的「视频片段」。
  - **回放**：点「回放选中片段」播放选中行对应的视频片段（D 已切好的 `segment_xxx.mp4`）。未选中时点会提示先选一条。
  - 每条结果本质是「事件 + 时间 + 描述 + 片段」的一体记录。

## 五、完整运行效果（一次典型操作）

以「本地视频文件」为例，从打开到回放的完整流程：

1. **导入视频**：切到「本地视频文件」Tab，上传一段学习录像。
2. **开始分析**：点「开始分析」，状态变绿「运行中」，画面开始叠加检测框（Day 2 起），`LIVE` 检测区逐帧跳动。
3. **事件逐步出现**：视频播到 10:32，学生拿起手机 —— 右上「当前事件」切换成「玩手机」，时间线追加一条「10:32 玩手机（当前）」。
4. **语义理解更新**：命中「玩手机」事件时，「语义理解」区刷新成对应描述。
5. **停止**：点「停止分析」，分析链路停止，状态变「已停止」。
6. **搜索**：在搜索框输入「什么时候有人玩手机？」，点搜索，结果表格列出匹配的记录。
7. **回放**：点击「10:32:15 玩手机」那一行，再点「回放选中片段」，播放那段视频片段。

**最终效果**：用户不翻原视频，凭一句自然语言，就能定位到「学生玩手机的那一刻」，并直接回放那段画面。

## 七、技术备注

- **UI 框架**：Gradio（`gradio 6.x`），Python 3.11（`multimodal` 环境）。
- **图标**：内联 SVG（Lucide 线条风格），无 emoji。
- **视觉**：白底 + 蓝色点缀（`#2563eb`），卡片化布局。
- **三条对接接口**（与队友约定）：
  - C 检测追踪 → `{frame_id, timestamp, track_id, class, confidence, bbox}` → 用于 LIVE VIDEO 画框。
  - A 事件引擎 → `{event_type, track_id, start_time, end_time, confidence}` → 用于当前事件。
  - D 记忆检索 → `{event, timestamp, caption, video}` → 用于搜索结果 + 回放。
