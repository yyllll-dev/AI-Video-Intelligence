# VisionOracle 应用场景及用户价值说明

## 1. 项目定位

VisionOracle 面向需要回顾学习过程、定位具体行为片段和管理长视频信息的用户。它把一段连续视频转化为结构化事件时间线、客观摘要、有效时长统计和可点击回放，使用户不必从头反复拖动视频寻找关键片段。

系统的定位是“本地视频回顾与检索助手”，不是监控执法工具、身份识别系统或自动教育评价系统。

## 2. 核心问题

传统学习录像通常存在以下问题：

- 视频长、信息密度低，人工完整回看耗时。
- 想寻找“什么时候看手机”“什么时候开始阅读”时，只能反复拖动进度条。
- 单纯计算录像总时长不能反映具体行为的有效时长。
- 云端视频分析可能带来上传耗时、网络依赖和隐私顾虑。
- 只有一段自然语言总结时，用户难以回到原视频核实依据。

VisionOracle 通过“事件时间线 + 有效时长统计 + 自然语言搜索 + 原视频回放”把分析结论与视频证据连接起来。

## 3. 目标用户

| 用户 | 主要需求 | VisionOracle 提供的价值 |
|---|---|---|
| 学习者本人 | 回顾学习过程、快速找到分心或行为切换片段 | 减少人工浏览，提供可核验的时间线和回放 |
| 家长或学习陪伴者 | 在获得授权的前提下了解学习过程 | 用结构化事件代替持续盯看原视频 |
| 教师、辅导员或学习指导人员 | 复盘经授权的学习录像，辅助沟通 | 快速定位片段，基于原始画面讨论，而非只看模型结论 |
| 教育研究与人机交互研究人员 | 对受试者视频做初步整理 | 自动生成候选事件和时间范围，降低前期标注成本 |
| AI PC 展示与教学人员 | 演示端侧多模态 AI 应用 | 展示本地模型协作、实时视频处理与隐私友好部署 |

任何涉及他人拍摄、未成年人或教学评价的使用，都必须先满足知情、授权、数据保护和人工复核要求。

## 4. 主要应用场景

### 4.1 个人学习过程复盘

**使用者：** 学习者本人。

**典型流程：**

1. 学习者上传一段已经录制的视频，或使用摄像头记录本次学习过程。
2. 系统识别阅读、书写、手机使用、电脑使用和离开位置等事件。
3. 分析完成后，学习者查看事件时间线和有效时长占比。
4. 学习者搜索“手机”“什么时候离开座位”等问题。
5. 点击对应结果回看原视频片段，自行判断行为背景。

**用户价值：**

- 将长视频压缩为可浏览的事件目录。
- 快速定位需要反思的片段。
- 使用“有效总时长”区分已确认事件时间与原始录像长度。
- 每项结论都能打开视频回放，避免只有文字结论而无法核实。

### 4.2 经授权的学习指导

**使用者：** 家长、教师、辅导员或学习指导人员。

**适用前提：** 被拍摄者明确知道用途并同意采集和分析；分析结果仅用于沟通辅助。

**典型流程：**

1. 学习者主动提交需要复盘的录像。
2. 指导人员先查看整体事件顺序，再打开少量关键片段。
3. 双方结合原视频讨论环境、任务切换和分心原因。
4. 模型输出只作为定位线索，不直接形成评价或处罚。

**用户价值：**

- 降低完整观看长视频的时间成本。
- 让沟通围绕具体时间点和画面事实展开。
- 减少仅凭印象讨论学习状态的情况。

### 4.3 教育研究与视频初标注

**使用者：** 获得伦理审批和受试者授权的研究团队。

**典型流程：**

1. 将实验录像导入本地 AI PC。
2. 系统生成候选事件、关键帧和事件回放。
3. 研究人员逐条复核、修正或舍弃候选结果。
4. 通过结构化时间范围辅助后续人工标注和统计。

**用户价值：**

- 降低从零开始浏览和切分视频的工作量。
- 使初步标注过程具备统一事件词表。
- 数据可保留在本地设备，减少原始视频外发。

系统当前没有提供专业标注导出、多人协作和研究数据版本管理，因此只能作为初筛工具，不能替代正式标注平台。

### 4.4 本地视频档案快速检索

**使用者：** 需要整理少量本地学习录像的个人或项目组。

**典型流程：**

1. 对视频逐个完成本地分析。
2. 通过事件时间线和中文关键词定位行为片段。
3. 使用事件回放进行展示或复核。

**用户价值：**

- 把“文件名 + 视频进度条”升级为“事件 + 时间范围 + 回放”。
- 对明确事件词的搜索结果更直接，例如“手机”只返回使用手机事件。
- 不依赖外部向量数据库或云端检索服务。

当前记忆存储主要服务于单次运行，不适合作为大规模跨视频资产管理系统。

### 4.5 AI PC 端侧应用展示

**使用者：** 竞赛评委、开发者、教学人员和方案验证团队。

**展示内容：**

- YOLO11n 与 Qwen2-VL-2B-Instruct 在同一台设备本地运行。
- 轻量高频检测与低频多模态推理解耦。
- 上传视频和实时摄像头进入同一事件协议。
- 摄像头录制不因 VLM 推理速度改变视频时长。
- 本地生成事件、摘要、统计、搜索结果和回放。

**用户价值：**

- 直观展示 AI PC 对视觉感知、多模态理解和交互式检索的承载能力。
- 在网络不稳定或不希望上传原始视频的环境中保持核心功能。
- 为后续 OpenVINO、ONNX、量化和异构计算优化提供可运行基线。

## 5. 用户使用前后对比

| 环节 | 传统方式 | 使用 VisionOracle |
|---|---|---|
| 浏览长视频 | 从头播放或反复拖动 | 先浏览事件时间线 |
| 查找具体行为 | 凭记忆估计时间点 | 输入“手机”“阅读”等关键词 |
| 理解整体过程 | 人工记录行为顺序 | 自动生成客观事件摘要 |
| 统计行为时间 | 手工记时并汇总 | 自动计算已确认事件有效时长及占比 |
| 核实分析结论 | 重新寻找原视频位置 | 点击事件直接打开回放 |
| 数据处理位置 | 可能需要上传云端 | 模型和视频处理默认留在本机 |

## 6. 核心用户价值

### 6.1 节省回看时间

系统先把视频组织成事件列表，用户可以只打开与当前问题相关的片段。实际节省比例需要通过统一视频集和用户实验测量，本文不预设未经测试的百分比。

### 6.2 提升信息可检索性

用户不需要记住准确时间点，可以通过自然语言中的明确事件词定位结果。当前检索优先保证可解释性和事件类型准确过滤，而不是追求开放域问答能力。

### 6.3 分析结果可核验

时间线、摘要和图表均关联原始时间范围。用户可以回到对应视频证据，判断模型是否误判，避免把模型文字当作不可质疑的事实。

### 6.4 保护视频隐私

检测、VLM 推理、统计、检索和回放生成均可在本地完成。模型准备完成后，核心分析不依赖云端推理 API，降低原始视频离开设备的必要性。

### 6.5 适配 AI PC

系统采用小型 YOLO11n 和 2B 视觉语言模型组合，并通过降采样、关键帧、缓存复用和异步处理控制计算量，适合展示端侧多模型协同，而不是把每一帧都交给大模型。

## 7. 差异化特点

- **规则与模型协作：** 不让 YOLO 或 VLM 单独承担全部行为判断。
- **事件证据闭环：** 摘要、图表、搜索结果最终都可以落到视频回放。
- **真实时间轴：** 摄像头录像按实际采集帧率编码，事件时间与完整录像保持同一基准。
- **输入方式一致：** 上传视频和摄像头使用统一事件类型、总结和检索界面。
- **本地优先：** 不依赖收费多模态 API，不要求上传原始视频。
- **边界透明：** 长事件明确标记为摘要回放，不把 60 秒摘要伪装成完整事件录像。

## 8. 隐私、伦理与安全原则

1. **知情同意：** 拍摄和分析前明确说明目的、保存时间和访问范围。
2. **数据最小化：** 只采集完成目标所需的视频，不采集实时摄像头音频。
3. **本地优先：** 原始视频、关键帧和回放默认保存在本机。
4. **可删除：** 演示或分析完成后，可以清理 `data/` 和日志。
5. **人工复核：** 所有行为结论都应允许用户查看对应视频片段。
6. **避免标签伤害：** 不从画面推断学习态度、人格、能力、身份或动机。
7. **限制访问：** 含个人画面的运行数据不得直接提交到公开仓库。

## 9. 商业与落地边界

当前版本是本地原型和参赛展示系统。若进入真实产品阶段，还需要补充：

- 明确的数据控制者、保存期限和删除机制。
- 用户登录、权限控制、访问审计和数据加密。
- 针对目标场景采集的合法评测集。
- 人工纠错、事件编辑和结果导出功能。
- 模型偏差、误报和漏报监测。
- Ultralytics、Qwen 及全部依赖的许可证合规审查。
- 针对儿童或教育数据的额外法律和伦理评估。

## 10. 结论

VisionOracle 的主要价值不在于替用户评价学习状态，而在于把难以浏览的长视频整理成可搜索、可统计、可回放的本地事件记忆。它帮助用户更快找到事实片段，同时保留原视频证据和人工判断权，适合作为个人学习复盘、经授权的视频初筛和 AI PC 端侧多模态应用展示的基础方案。
